# 複数枚同時アップロード＆圧縮のみモード 設計ドキュメント

日付: 2026-06-11
ステータス: 承認済み（実装前）

## 背景・目的

現状のアプリは画像1枚のみを受け付け、「リサイズ」「切り抜き」の2モードで処理する。
本変更で以下を実現する。

1. **複数枚同時アップロード**: 複数の画像を一度に入稿し、まとめて処理・ダウンロードできる
2. **圧縮のみモード**: サイズ（ピクセル数）を変えずにファイル容量だけ軽くするモードを追加。目標ファイルサイズ指定（自動品質調整）にも対応

引き続き**完全クライアントサイド処理**とし、画像はサーバーに送信しない。

## 決定事項（ユーザー確認済み）

| 論点 | 決定 |
|---|---|
| 複数枚×切り抜き | サムネイルで1枚ずつ切り替えて、画像ごとに範囲を指定する |
| 複数枚×リサイズ | 同じく1枚ずつ切り替えて、画像ごとに幅×高さを指定する |
| ダウンロード | ZIP一括＋個別ダウンロードの両方 |
| 圧縮のみモード | 品質スライダーに加えて目標ファイルサイズ（KB）指定を追加 |
| 画面構成 | 案A: サムネイル切り替え方式 |

## UI仕様

### アップロード（ImageDropzone）

- `<input type="file">` に `multiple` を付け、ドラッグ&ドロップも複数ファイルを受け付ける
- `image/*` 以外のファイルは除外する。全ファイルが対象外だった場合のみ「画像ファイルを選択してください」と通知する（一部のみ対象外の場合は黙って除外し、画像だけ読み込む）
- コールバックは `onFiles(files: File[])` に変更する

### サムネイル帯（ThumbnailStrip / 新規コンポーネント）

- メインプレビューの上に横スクロール可能なサムネイル一覧を表示する（1枚のときも表示する）
- クリックで編集対象（選択中画像）を切り替える。選択中はインディゴ枠でハイライト
- 各サムネイルに削除（×）ボタン。削除時は当該画像のリソース（objectURL / ImageBitmap）を解放する。選択中の画像を削除した場合は隣の画像を選択し、0枚になったらアップロード画面に戻る
- 各サムネイルに処理状態を表示: 未処理（無印）/ 処理中（スピナー）/ 完了（✓）/ 失敗（!）
- 末尾に「＋追加」ボタン。クリックでファイル選択ダイアログを開き、既存リストの末尾に追加する

### モードタブ（ModeTabs）

3タブに変更する（モードは全画像共通）。

| 値 | ラベル | 説明文 |
|---|---|---|
| `resize` | リサイズ | 縦横ピクセル数に縮小/拡大 |
| `crop` | 切り抜き | 範囲を指定して切り抜き |
| `compress` | 圧縮のみ | サイズはそのまま容量を軽量化 |

### 設定の持ち方

- **画像ごと**: リサイズの幅×高さ、切り抜き範囲。サムネイルで切り替えると、その画像に保存済みの値が復元される
- **全画像共通**: モード、出力形式、品質、目標ファイルサイズ

### 切り抜き（CropControls）

- props に「初期範囲（PercentCrop）」を追加し、画像切り替え時に保存済みの範囲を復元できるようにする
- 範囲変更時はピクセル換算の `CropArea` に加えて `PercentCrop` も親へ通知し、親が画像ごとに保持する
- コンポーネントは選択中画像の id を `key` にして再マウントする
- アスペクト比プリセットの選択状態は従来通りコンポーネント内部の状態とする（画像を切り替えると「自由」に戻るが、保存済みの範囲自体は復元される）

### 圧縮のみモード（右パネル）

- 寸法指定の UI は表示しない。出力形式・品質スライダーに加えて「目標ファイルサイズ（KB）」の数値入力欄を表示する
- 目標サイズが空欄のときは品質スライダーの値をそのまま使う
- PNG 選択時は品質調整が効かないため、目標サイズ入力を無効化し「PNGは可逆圧縮のため目標サイズ指定は使えません。JPEG/WebPを選択してください」と注記する

### 処理ボタン

- ラベル: 1枚なら「画像を処理する」、2枚以上なら「すべて処理する（n枚）」
- 処理中は「処理中… (i/n)」と進捗を表示する
- ヘッダーの「別の画像を選ぶ」は「すべてクリア」に変更する

### 結果一覧（ResultsPanel / ResultPanel を複数対応に改修）

- 処理済みの各画像について、サムネイル・寸法・元容量・出力容量・削減率・個別ダウンロードボタンを縦に並べて表示する
- 2枚以上処理済みのときは先頭に「ZIPでまとめてダウンロード」ボタンを表示する
- 一部の画像が失敗した場合は、その画像の行にエラーメッセージを表示し、成功分のみダウンロード可能とする

## データ構造（lib/types.ts）

```ts
export type Mode = "resize" | "crop" | "compress";

export type ImageItem = {
  id: string;                    // crypto.randomUUID()
  source: SourceImage;           // 既存型をそのまま使用
  resize: { width: number; height: number };  // 初期値: 元寸法
  percentCrop: PercentCrop | null;             // 切り抜きUIの復元用
  cropArea: CropArea | null;                   // ピクセル換算の切り抜き範囲
  status: "idle" | "processing" | "done" | "error";
  result: ProcessResult | null;
  error: string | null;
};
```

- `OutputOptions` に `targetSizeKB?: number` を追加する
- `ProcessOptions` の `mode` に `"compress"` を追加する（`resize` / `crop` は不要）
- `ProcessResult` に `metTargetSize?: boolean` を追加する（目標サイズ指定時のみ設定）

## 処理仕様（lib/imageProcessor.ts）

### 圧縮のみモード

- 元の寸法のまま（`dWidth = bitmap.width, dHeight = bitmap.height`）再エンコードする

### 目標ファイルサイズ（JPEG/WebP のみ）

- 品質 0.05〜1.0 の範囲で二分探索し、`size <= targetSizeKB * 1024` を満たす最高品質を探す（最大8回エンコード）
- 最低品質でも目標を超える場合は最低品質の結果を返し、`metTargetSize: false` とする。結果一覧に「目標サイズに届きませんでした」と表示する
- 目標を満たした場合は `metTargetSize: true`

### 複数枚の処理

- 1枚ずつ順次処理する（並列にしない。メモリ消費と UI フリーズを抑えるため）
- 各画像の成否は `ImageItem.status` / `error` で個別管理し、1枚失敗しても残りは継続する
- 処理開始時に全 item の `result` をクリアする

### ZIP 生成

- ライブラリ **fflate** を dependencies に追加する（軽量・依存なし）
- 出力画像は既に圧縮済みのため、ZIP は無圧縮（level 0 / store）で固める
- ZIP ファイル名: `images_processed.zip`
- 各エントリ名は個別ダウンロードと同じ命名規則。同名衝突時は `name_2.jpg` のように連番を付与する

### ファイル命名（現行踏襲）

- `元のベース名_processed.{jpg|png|webp}`

## エラー処理

- **読み込み失敗**: 失敗したファイルだけスキップし、ファイル名付きでメッセージを表示。読めた画像は通常通り追加する
- **処理失敗**: 当該 item の `status: "error"` とし、結果一覧とサムネイルにエラー表示。他の画像の処理は継続する
- **リソース管理**: 画像の削除・全クリア・差し替え時に `URL.revokeObjectURL` と `bitmap.close()` を必ず呼ぶ（既存の `disposeSource` を流用）

## 依存関係の追加

- `fflate`（ZIP生成、ブラウザ内で完結）

## 検証方法

自動テスト基盤がないため、開発サーバー＋Playwright で以下を手動検証する。

1. 複数枚（サイズの異なる3枚程度）を一括ドロップ → サムネイル表示
2. リサイズ: 画像ごとに異なる幅×高さを設定 → 切り替えても値が保持される → 全処理で各画像が指定寸法になる
3. 切り抜き: 画像ごとに異なる範囲を指定 → 切り替えても範囲が復元される → 全処理で正しく切り抜かれる
4. 圧縮のみ: 寸法が変わらず容量が減る。目標サイズ指定で目標以下になる。PNG 選択時に目標サイズ入力が無効化される
5. ZIP一括ダウンロード → 中身のファイル数・ファイル名・内容を確認
6. 1枚だけの場合に従来同等の操作感（ZIPボタン非表示）
7. 画像の削除・追加・すべてクリアの動作
8. 1枚だけ壊れたファイルを混ぜた場合に他の画像の処理が継続される

検証で生成したスクリーンショット等の生成物は終了時に削除する。

## スコープ外（やらないこと）

- 切り抜き・リサイズ設定の「全画像に一括適用」機能
- 処理の並列化・Web Worker 化
- アップロード枚数の上限設定（多数枚でのメモリ逼迫は既知の制限とする）
- リサイズ／切り抜きモードへの目標ファイルサイズ指定の適用（圧縮のみモード限定とする）
